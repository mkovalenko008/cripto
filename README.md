# Bitget автотрейдер (ETH/USDT) — учебный каркас

Это не готовая "печатная машина денег", а рабочий каркас с базовыми
предохранителями, в который нужно вставить свою торговую логику.
Сейчас в `strategy.py` лежит простейший пример на RSI — его нужно
протестировать и, скорее всего, заменить.

## Перед тем как начать — важное

- **$1 за сделку — это ровно минимальный размер ордера на Bitget Spot.**
  Комиссия (0.1%) на такой сумме — копейки, но и сама позиция настолько мала,
  что бот при таком размере полезен как **тренировочный полигон для проверки
  логики**, а не как источник дохода. Увеличивай `TRADE_SIZE_USDT` в `.env`,
  когда убедишься, что всё работает как задумано.
- Это не финансовый совет и не гарантия прибыльной стратегии. RSI-пример —
  просто демонстрация архитектуры.
- Полный автопилот на реальных деньгах — это код, который будет действовать
  без твоего подтверждения. Обязательно пройди все шаги ниже по порядку.

## Настройка API-ключа на Bitget

1. Bitget → API Management → Create API Key.
2. Права: **Spot Trade** — да. **Withdraw** — НЕТ (обязательно отключи).
3. Привяжи ключ к своему IP, если бот крутится на постоянном сервере.
4. Сохрани `API Key`, `Secret Key`, `Passphrase` — passphrase потом нельзя
   посмотреть повторно.

## Установка

```bash
cd bitget_bot
python3 -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env` своими ключами. `DRY_RUN=True` оставь как есть на первом этапе.

## Порядок запуска (важно соблюдать по шагам)

1. **DRY_RUN=True, без ключей.** Убедись, что `get_candles` работает и бот
   пишет в `bot.log` вменяемые RSI-сигналы:
   ```bash
   python main.py
   ```
2. **DRY_RUN=True, с ключами.** Добавь ключи в `.env`, чтобы проверить
   `get_balance()` — бот должен корректно увидеть баланс, не отправляя ордера.
3. **Проверь одну реальную сделку вручную** через `bitget_client.py` в python
   REPL (`place_market_buy` / `place_market_sell` на минимальный размер),
   чтобы убедиться в правильности единиц измерения `size` для твоей пары —
   биржи меняют такие детали без предупреждения.
4. **DRY_RUN=False.** Только после того, как первые три шага прошли чисто и
   ты несколько дней смотрел логи в dry-run и был согласен с решениями бота.

## Предохранители, которые уже встроены

- **Kill switch**: создай пустой файл `STOP` в папке бота — на следующей
  итерации (максимум через `POLL_INTERVAL_SECONDS`) бот остановится.
  ```bash
  touch STOP
  ```
- **Дневной лимит убытка** (`MAX_DAILY_LOSS_USDT`): если реализованный PnL
  за сегодня уходит ниже лимита — новые сделки блокируются до полуночи UTC.
- **Лимит сделок в день** (`MAX_TRADES_PER_DAY`): защита от зацикливания.
- Всё логируется в `bot.log` (действия) и `trades_log.jsonl` (сделки,
  построчный JSON — удобно парсить).

## Paper-trading на GitHub Actions (без реальных денег)

`paper_trader.py` — отдельный скрипт, симулирующий стратегию `bb_strategy.py`
на живых ценах ETHUSDT с вымышленным балансом (по умолчанию $10). Реальные
ордера не отправляются никогда — скрипт даже не импортирует функции
размещения ордеров. Ключи API не нужны — используются только публичные
данные (`get_candles`).

Крутится через GitHub Actions (`.github/workflows/paper_trader.yml`) —
раз в 15 минут запускает одну проверку (`python3 paper_trader.py --once`) и
коммитит обновлённое состояние (`paper_state.json`,
`paper_trades_log.jsonl`, `PAPER_STATUS.md`) обратно в репозиторий. Текущий
статус смотри в [PAPER_STATUS.md](PAPER_STATUS.md).

Остановить: закоммитить пустой файл `STOP` в корень репозитория (следующий
прогон это увидит и пропустит проверку), либо отключить workflow во вкладке
Actions на GitHub.

Локально (без GitHub): `python3 paper_trader.py --capital 10 --duration-hours 24`.

## Что стоит доделать, прежде чем доверять этому реальные деньги

- Учёт комиссии в расчёте PnL (сейчас PnL считается без вычета комиссии).
- Обработка частичного исполнения ордеров и реальной цены исполнения
  (сейчас используется цена последней свечи, а не фактическая цена сделки).
- Backtest стратегии на исторических свечах перед боевым запуском.
- Уведомления в Telegram при сделках/ошибках (у тебя уже есть похожий паттерн
  в "Автопилоте блога" — можно переиспользовать тот же подход с ботом и
  chat_id).
